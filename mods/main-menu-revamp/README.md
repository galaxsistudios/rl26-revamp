# main-menu-revamp

Redesigns the home screen:

- **Menu boxes on the left**, under the top-left logo, in four tabs (LB/RB switch):
  - **Play**: Casual Game, Competitions, Career, Online (Pro Team is in Online's sub-menu). Casual Game and
    Competitions open a second page in place: Casual -> Team / Player, each with Male / Female;
    Competitions -> NRL, Super League, NRLW, WSL, Competition, World Cup. Each page has a Back box, and B also
    goes back. Coming back from a game reopens the page you left from.
  - **Academy**: unchanged.
  - **Settings**: the Settings sub-menu as boxes (General, Gameplay Sliders, Audio, Controls, ...).
  - **Extras**: Practice, Credits, About.
  Finals is gone. Boxes with sub-menus show a chevron, and the sub-menu flies out to the right of the box.
- **A random NRL player on the right.** Each time the home screen opens, a random player from a random NRL club
  stands on the right in that club's home kit, always holding a ball in the left hand. The ball prop declares
  `LeftHandBallJoint`, but `setPlayerModelProps` attaches without a joint and `flushPropAttachments` falls back to
  `RightHandBallJoint`, so the hook names the joint. The hand is per animation (`MainMenuBallHands`: `left` /
  `right` / `none`, keyed by action set). Work the values out with storm-celebration-viewer's Ball row.
- **Animations.** The player idles with the ball, and every 7-11 s plays a flourish before going back to the idle:
  the approval gesture or one of the ten Pro Team card poses (`rl1_proteam_screenshot_01`-`10`). Only sets with
  a `Ball` variant are used. `HeroPose` has none, and through it the ball stayed stuck to one hand. The no-ball
  pool (jersey pose, arms-cross) is kept in `MainMenuFlourishes.noBall` for `ballChance < 1`.

The Featured promo banner is hidden, because the right half of the screen belongs to the player.

Needs script bundle **39959** and Noesis bundle **57662**.

## How it works

### Player (Lua)

- **Hook.** `homescreen_state.lua` belongs to allow-exit-any-menu-tab, so `HomeScreenState.enter/update/exit`
  are wrapped. `compresssavedata_state` is `homescreen_state`'s first import, and nothing else imports or
  overrides it, so it hosts the code. `Class()` reuses an existing `_G._CLASSES.HomeScreenState`, so the hook
  pre-seeds it with a metatable. The wrapped methods are never stored raw in the class. They sit in a side
  table behind `__index`, so every definition, including the re-import of the frontend scripts after a match,
  goes through `__newindex` and is wrapped again. clear-academy-data's `update` trap on the same metatable is
  chained.
- **Finding uiServices.** The engine's `type()` returns class names for instances (`FrontEndServices`), so
  table checks use `rawtype`. The first in-game run missed the services for this reason and showed no player.
- **Player.** NRL club ids come from `leagueManager.onDisc:getLeagueIdBasedOff(AcademyLeagues.League_NRL2026)`
  (then `League_NRL`), `getLeague(id):getClubIds()`. If that fails it uses the 2026 NRL clubs 118-134. It picks
  a random club, then a random roster player (`club:getPlayerIdAt`, `playerManager:getPlayer`, so Academy edits
  show). The mod uses its own random generator, so the game's `math.random` sequence is untouched.
- **Model.** Player model 1, the same one the player-edit screens use: `playerModelCameraEnabled(true)`, which
  must come before the camera is set, because enabling it clears every model's camera info. Then
  `playerModelSetUniform(club:getHomeUniformVisual())`, the `ball` prop attached (or detached), and
  `playerModelUpdate` with `hideUntilLoaded`, rotation 15 deg (turned toward the menu) and a camera table copied
  from `FullBody_OutsideOfAppearance`, the player-edit framing that puts a full-body player on the right.
- **Animations** are front-end action sets (`intermediatelua/animations/frontendset.lua`), queued with
  `idleParams` and a 12-frame cross-blend. The idle timer starts once the model has loaded. With the ball, only
  sets with a `Ball` variant or no gear filter can play. A set that filters down to nothing is skipped by the
  engine, so the idle just carries on. The `rl1_proteam_screenshot_NN` poses are left out because they're
  authored for a sideways card-render camera. Tune everything in `MainMenuConfig` / `MainMenuFlourishes`.
- **Exit.** When the home screen exits, the ball is detached, the model is hidden, the model camera is popped
  (unless it was already on) and model 1's previous camera info is put back (at boot that's the featured
  player's). Screens that don't set their own camera therefore see no change. Each step runs on its own, so
  one failure can't leave the camera pushed.
- `enter` only shows the player when the menu was built (`self.view`). The standalone and `autoNavTo` paths
  hand straight over to another state.

### Menu layout (Lua)

- `homescreenstate_config.createFirstPageTiles` (owned by coach-editor) is wrapped at home-screen enter. The rows
  stay Main / Competition / Academy / Extra, because NVMHomeScreen builds one view-model per row. Within them:
  Casual becomes CasualGame (page button) + CasualTeam / CasualPlayer (accordions split from its 4 items by
  `beAPro`). Online becomes OnlineMenu (no tile `stateFactory`, so each sub-button uses its own: Online setup,
  or Dynasty for Pro Team). Finals and ProTeam are dropped, RLWC2026 is retitled World Cup, and the Settings
  accordion becomes SettingsItem1..N. The tile tables are shared, so every change is made on a copy.
- **New tile keys need bound properties**, and `ns.Class` turns `Bindings` into a native type the moment it is
  assigned. So `_CLASSES.MainNVM` / `ExtraNVM` are pre-seeded, with a metatable on their metatable. When ns
  installs its one-shot `__newindex` Bindings handler, that's caught and wrapped to add `Page`, the new tiles
  and 12 settings slots. This also works on the re-registration after a match.
- **Pages.** Page buttons select like any tile (`stateData.mainMenuPage`). The update hook takes that
  selection before the stock code would change state, sets `Main.Page` (bound; XAML shows the page) and moves
  focus (`FocusElementIdentifier` + `ForceElementFocus`, plus a XAML `SetFocusAction`). B on a page goes back.
  The stock "B on the first tab = exit game" timer is held off while a page is open. On enter, the last
  highlighted tile's page is reopened.
- **Not kept:** Pro Team's strict UGC privilege check. The stock code reads it from the highlighted tile, and
  that's now Online.

### Menu (XAML)

- **Rows inlined.** The stock tab items host `pa*TileRow.xaml` user controls (horizontal rows).
  `pahomescreenview.xaml` builds its own stacks instead (layout in `make_xaml.py`'s `PLAY_PAGES` etc.). Icons
  come from the stock rows. The Play tab's DataContext is the root VM, so it can mix `Main.*` and
  `Competition.*` tiles. The four row files are left alone (about-rl26-revamped owns `paextratilerow.xaml`). Its NTS
  "info" icon is copied in when that mod is present. Hidden tiles still collapse through the stock
  null-DataContext trigger. Icon-less competition tiles get the tab's trophy icon.
- **Tab control.** It has its own template, a copy of `MainMenuTabControlTemplate` with text tabs and a content
  row that grows (stock: a fixed 120 px row, which would clip a vertical stack). `PART_SelectedContentHost` and
  the `subMenuOpen` fade are kept.
- **Plain tiles** (Pro Team, Comms, Practice, Credits, NTS) set `Template="{StaticResource MenuBoxButtonTemplate}"`
  locally. paButton styles itself from its own XAML, so a local template beats the implicit style and keeps its
  bindings.
- **Accordion tiles** set `Tag="MenuBox"`. A trigger added last in the accordion's own Style swaps in
  `MenuBoxAccordionTemplate`. That template keeps the stock named parts (`RootStackPanel`, `FocusHelperBorder`,
  `InternalButton`, `AccordionItemsControl`), visual states, focus engagement and code-behind handlers
  (`paAccordionButton_PreviewLostKeyboardFocus`, `IsExpandedStoryboard_Completed`, `paSubButton_Loaded`). Only the
  position changes: the sub-buttons stay in a Canvas like stock, placed to the right of the box instead of above
  the tile. A first version put the ItemsControl in a Grid row below the box (inline accordion). In game no
  sub-buttons showed, and the native focus trap then left the open box stuck (force quit). The native control
  (0x140386f10, `paAccordionButton_PreviewLostKeyboardFocus`) cancels any focus move outside
  `AccordionItemsControl` while expanded, and only a sub-button's `Loaded` (0x140386f70) moves focus in. If the
  sub-buttons don't load, there's no way out. It's
  defined in the same x:Class file, so the handlers resolve exactly as they do for the stock template. Every
  other accordion (pause menu, dynasty, ...) has no Tag and keeps the stock template.
- **Box visual states** use the stock names (`NormalVisualState`, `IsFocusedVisualState`,
  `IsSelectedVisualState`), which the native paButton drives. Their brushes are local, so animating them doesn't
  touch the shared `RL*` brushes.
- **Promo banner.** The stock banner and its named parts and handlers are kept but `Collapsed`, in case the
  native code-behind looks them up.
- **Layout** is in the 1920x1080 space of `baScreenControl`: column at x=150, y=172, 640 wide. Boxes are 440x50
  with a 6 px gap. Flyouts are 310 wide at x=616, between the menu and the player.

Regenerate the XAML after a game update (restore 57662 first if a modded build is installed):

```powershell
python tools\extract_m3mp.py --entry xamls --out <tmp>\57662
python mods\main-menu-revamp\make_xaml.py --stock <tmp>\57662\noesis\workspace
```

## Install

Close the game first.

```powershell
python tools\build.py full --confirm
python tools\extract_m3mp.py --entry xamls --out <tmp>\57662
python tools\build.py full --list manifests\xamls.xml --extracted <tmp>\57662 --out _build\xamls.m3mp --confirm
```

## Status

**Working in game (2026-10-27):** the Play / Academy / Settings / Extras layout, Casual and Competitions pages
(focus on the first box, B closes an open sub-menu before leaving a page), the flyout sub-menus, and the random
NRL player with animations.

Fixes found while testing in game:
- **Sub-menus.** Replacing the whole accordion template from a Style trigger showed no sub-buttons and locked focus
  (the native focus trap). Triggers added inside the stock template work.
- **Player.** The engine's `type()` returns class names, which hid uiServices. Use `rawtype`.
- **Page focus.** Neither a SetFocusAction on `Main.Page` nor runtime `FocusElementIdentifier` worked. Focus goes
  through `Main.FocusRequest`, set 2 frames after the page change.
- **Head tracking** (`lookAtEnable`) looked wrong with the flourishes, so it's off (`MainMenuConfig.lookAtCamera`).

`MainMenuDebug` is still `true` (trace in `mainmenu_debug.txt` in the game folder). Turn it off for a release
build. Real errors are always logged.
